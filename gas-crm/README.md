# CRM Spunky Food (Google Apps Script)

ระบบ CRM สำหรับติดตามลูกค้าที่ติดต่อขอนำสินค้าไปขายต่างประเทศ — เวอร์ชันนี้รันบน **Google Apps Script**
เก็บข้อมูลใน **Google Sheet** ที่สร้างขึ้นอัตโนมัติ ไม่ต้องหา hosting ไม่ต้องมีคนดูแลเซิร์ฟเวอร์
เหมาะกับการใช้งานคนเดียวหรือทีมเล็ก ๆ

## มีอะไรบ้าง
1. ข้อมูลลูกค้า (บุคคลธรรมดา/บริษัท) + Dropdown ประเทศที่จะส่งไปขาย + ช่องทางติดต่อ + สถานะลูกค้า (ติ๊กเปลี่ยนได้ทันทีจากหน้ารายชื่อ/หน้ารายละเอียด)
2. แดชบอร์ดสรุปยอด + ส่งรายงานสรุปประจำวันเข้ากลุ่ม **LINE** อัตโนมัติ
3. แจ้งเตือนใบเสนอราคาใกล้หมดอายุ / วันจัดส่งใกล้ถึง / นัดติดตามลูกค้าที่ครบกำหนด — ขึ้นเป็นแถบแจ้งเตือนบนหน้าเว็บโดยตรง (แดชบอร์ด + หน้ารายละเอียดลูกค้า)
4. อัปโหลดเก็บเอกสาร (ใบเสนอราคา/PO/ใบแจ้งหนี้/สลิปการโอนเงิน/ใบส่งของ/ใบรับสินค้า/ใบเสร็จ) รองรับไฟล์ PDF, JPG, PNG ไว้ใน Google Drive อัตโนมัติ
5. AI วิเคราะห์ลูกค้าที่ยังไม่ปิดดีล (ใช้ Claude API)
6. อ่านข้อมูลสินค้าสด ๆ จากชีต "Master Data Sales" > แท็บ "SKU ส่งออก" และเลือกแนบเป็น "สินค้าที่สนใจ" ตอนสร้างดีลได้เลย (หรือพิมพ์เองถ้าไม่มีในรายการ)
7. โลโก้บริษัท (ไฟล์ `Logo.png` วางไว้ข้าง `Index.html`) แสดงที่แถบด้านบนของเว็บ
7b. รองรับฝากหน้าเว็บไว้แยกที่อื่น เช่น **GitHub Pages** โดยเรียกฐานข้อมูล/เซิร์ฟเวอร์ที่ยังรันบน Apps Script ผ่าน API ที่มี Token ป้องกัน (ดูหัวข้อ "วิธีฝากหน้าเว็บไว้ที่ GitHub Pages" ด้านล่าง)
8. เมื่อกด **"ปิดการขายสำเร็จ"** ระบบจะเปิดหน้าต่างให้กรอกยอดขายจริง/ช่องทางโฆษณา (Ad)/วิธีชำระเงิน แล้วบันทึกเข้าชีต **Revenue** ให้อัตโนมัติ พร้อมต่อเลขที่บิลจากเลขล่าสุดในชีตให้เอง และดึงสลิปการโอนเงินที่แนบไว้มาใส่ Slip1 ให้ (กันบันทึกซ้ำในตัว)
   - สถานะลูกค้ามีจุดแก้ไขจุดเดียวคือ dropdown สถานะที่ตัวดีล (badge ที่หัวข้อมูลลูกค้าเป็นแค่ตัวโชว์ผล ไม่ใช่ตัวกด)

## วิธีติดตั้ง (ทำครั้งเดียว ใช้เวลาประมาณ 15-20 นาที)

### ขั้นที่ 1: สร้างโปรเจกต์ Apps Script
1. ไปที่ **https://script.google.com**
2. กด **โปรเจกต์ใหม่ (New project)**
3. ตั้งชื่อโปรเจกต์ (มุมซ้ายบน) เป็น **CRM Spunky Food**

### ขั้นที่ 2: วางไฟล์โค้ดทั้งหมด
โฟลเดอร์นี้มีไฟล์โค้ด 9 ไฟล์ (.gs) และไฟล์หน้าเว็บ 1 ไฟล์ (.html) ต้องสร้างในโปรเจกต์ให้ครบ **ชื่อไฟล์ต้องตรงกันเป๊ะ**

1. ไฟล์ `Code.gs` ที่มีอยู่แล้วในโปรเจกต์ (ชื่อเริ่มต้นคือ Code.gs) → **ลบโค้ดเดิมทั้งหมด** แล้ว copy เนื้อหาจากไฟล์ `Code.gs` ในโฟลเดอร์นี้ไปวางแทน
2. กดเครื่องหมาย **+** ข้างคำว่า "Files" → เลือก **Script** → ตั้งชื่อ `Constants` (ไม่ต้องพิมพ์ .gs) → วางเนื้อหาจากไฟล์ `Constants.gs`
3. ทำซ้ำขั้นตอนที่ 2 สำหรับไฟล์ที่เหลือ (สร้างไฟล์ประเภท **Script** ทุกไฟล์):
   - `Reminders` ← เนื้อหาจาก `Reminders.gs`
   - `Documents` ← เนื้อหาจาก `Documents.gs`
   - `Ai` ← เนื้อหาจาก `Ai.gs`
   - `Skus` ← เนื้อหาจาก `Skus.gs`
   - `Settings` ← เนื้อหาจาก `Settings.gs`
   - `Revenue` ← เนื้อหาจาก `Revenue.gs`
   - `Api` ← เนื้อหาจาก `Api.gs`
4. กด **+** อีกครั้ง → เลือก **HTML** → ตั้งชื่อ **Index** (สำคัญมาก ต้องชื่อ Index พอดี ตัวพิมพ์ใหญ่-เล็กตรงกัน) → วางเนื้อหาจากไฟล์ `Index.html`
5. (ไม่บังคับ) เปิดไฟล์ `appsscript.json`: กดไอคอนเฟือง **Project Settings** (ด้านซ้าย) → ติ๊ก "Show appsscript.json manifest file in editor" → จะมีไฟล์ appsscript.json โผล่มาในรายการไฟล์ → วางเนื้อหาจากไฟล์ `appsscript.json` ในโฟลเดอร์นี้ทับ (ช่วยตั้ง timezone ให้ถูกต้อง)
6. กด **บันทึก** (รูปแผ่นดิสก์ หรือ Ctrl+S)

### ขั้นที่ 3: สร้างฐานข้อมูล (รันครั้งเดียว)
1. ที่แถบด้านบน เลือกฟังก์ชัน **setup** จาก dropdown (ข้าง ๆ ปุ่ม Run รูปสามเหลี่ยม)
2. กด **Run** (▶)
3. จะมีหน้าต่างขอสิทธิ์ **Authorization required** ขึ้นมา → กด **Review permissions** → เลือกบัญชี Gmail ของคุณ → ถ้าเจอหน้า "Google hasn't verified this app" ให้กด **Advanced** → **Go to CRM Spunky Food (unsafe)** → กด **Allow**
   (ปลอดภัย เพราะเป็นสคริปต์ของคุณเองที่เพิ่งสร้าง ไม่ใช่ของคนอื่น)
4. รันเสร็จแล้วดูที่ **Execution log** ด้านล่าง จะมีลิงก์ Google Sheet ที่สร้างขึ้นชื่อ **"CRM Spunky Food Database"** — เปิดดูได้เลยว่ามีชีตอะไรบ้าง

### ขั้นที่ 4: Deploy เป็นเว็บแอป
1. กดปุ่ม **Deploy** (มุมขวาบน) → **New deployment**
2. กดไอคอนเฟืองข้าง "Select type" → เลือก **Web app**
3. ตั้งค่า:
   - **Execute as:** Me (อีเมลของคุณ)
   - **Who has access:** เลือก **Only myself** / **Anyone with Google account** ถ้าจะเปิดตรงจากลิงก์ Apps Script เท่านั้น — แต่ถ้าจะฝากหน้าเว็บไว้ที่ **GitHub Pages** ด้วย (ดูหัวข้อด้านล่าง) ต้องเลือก **Anyone** เพราะการเรียกจากภายนอกไม่มีการล็อกอิน Google ต้องพึ่ง API Token แทน (ระบบตรวจ Token ทุกครั้งอยู่แล้ว จึงยังปลอดภัย ตราบใดที่ไม่เผยแพร่ Token ให้คนอื่น)
4. กด **Deploy**
5. อาจขอ Authorize อีกรอบ → กด Allow เหมือนขั้นที่ 3
6. จะได้ **Web app URL** ขึ้นมา (ลงท้ายด้วย `/exec`) → **คัดลอกลิงก์นี้เก็บไว้** (นี่คือ URL ของฐานข้อมูล/เซิร์ฟเวอร์ ต้องใช้ตอนเชื่อมต่อหน้าเว็บ)

### ขั้นที่ 5: เปิดใช้งาน
1. เปิดลิงก์ Web app URL ที่ได้ในเบราว์เซอร์ → จะเห็นหน้าจอ **"🔌 เชื่อมต่อระบบ CRM"** ขึ้นมาก่อน (ครั้งแรกเท่านั้น)
   - ช่อง **Web App URL** จะกรอกให้อัตโนมัติ (เป็น URL หน้าปัจจุบัน)
   - กดปุ่ม **"สร้าง Token ใหม่ (ครั้งแรกเท่านั้น)"** ระบบจะสร้าง API Token ให้อัตโนมัติ
   - กด **"เชื่อมต่อ"** → จะเข้าสู่หน้าแดชบอร์ด CRM (เบราว์เซอร์นี้จะจำ URL/Token ไว้ ไม่ต้องกรอกซ้ำอีก)
2. ไปที่แท็บ **"⚙️ ตั้งค่า"** ใส่ข้อมูล:
   - LINE Channel Access Token และ LINE Group ID (สำหรับส่งรายงานสรุปประจำวันเข้ากลุ่ม LINE — ดูวิธีหาค่าด้านล่าง)
   - Anthropic API Key (ถ้าต้องการใช้ AI วิเคราะห์ลูกค้า — ขอได้ที่ https://console.anthropic.com)
   - Google Sheet ID และชื่อแท็บของข้อมูลสินค้า (ค่าเริ่มต้นตั้งไว้ให้แล้วตามไฟล์ Master Data Sales)
3. กด **บันทึกการตั้งค่า**
4. เลื่อนลงมาที่การ์ด **"ส่งรายงานสรุปเข้ากลุ่ม LINE ทุกวัน"** → ตั้งเวลาที่ต้องการ → กด **เปิดใช้งานส่งอัตโนมัติ**
   (กด "ส่งทดสอบตอนนี้" เพื่อลองส่งดูก่อนได้)

### วิธีหา LINE Channel Access Token + Group ID
1. สร้าง LINE Official Account / Messaging API Channel ที่ https://developers.line.biz/console/ (ถ้ายังไม่มี)
2. ในหน้า Channel → แท็บ **Messaging API** → เลื่อนลงไปที่ **Channel access token** → กด **Issue** แล้วคัดลอกมาใส่ในหน้าตั้งค่า
3. เชิญบัญชี Official Account (แอด LINE OA เป็นเพื่อน) เข้ากลุ่ม LINE ที่ต้องการให้ส่งรายงานไป
4. หา Group ID: เปิดใช้งาน Webhook ชั่วคราวหรือใช้เครื่องมือ เช่น LINE Bot Designer/logging เพื่อดู `groupId` ที่ส่งมาตอนมีข้อความในกลุ่ม (วิธีที่ง่ายที่สุด: ใช้ LINE Notify แทนก็ได้ถ้าไม่สะดวกหา Group ID — บอกผมได้ถ้าอยากเปลี่ยนไปใช้ LINE Notify แทน Messaging API)

### โลโก้บริษัท
โลโก้เป็นไฟล์ภาพธรรมดาชื่อ **`Logo.png`** ที่ต้องวางไว้ในโฟลเดอร์เดียวกับ `Index.html` เท่านั้น (ไม่ได้ดึงจาก Google Drive แล้ว)
- ถ้าเปิดเว็บตรงจาก Apps Script (ขั้นที่ 5) จะไม่เห็นโลโก้ เพราะ Apps Script ไม่ได้เก็บไฟล์ `Logo.png` ไว้ด้วย — ระบบจะโชว์ไอคอน 🌏 แทนโดยอัตโนมัติ ไม่ error อะไร
- ถ้าฝากไว้ที่ **GitHub Pages** (หัวข้อถัดไป) แค่ใส่ไฟล์ `Logo.png` ไว้ในไฟล์ repo เดียวกับ `Index.html` โลโก้จะขึ้นเองอัตโนมัติ

## วิธีฝากหน้าเว็บไว้ที่ GitHub Pages (ไม่ต้องขึ้นแบนเนอร์ "created by a Google Apps Script user")

ระบบรองรับการแยกส่วน **หน้าเว็บ (Index.html)** ไปฝากไว้ที่ไหนก็ได้ (เช่น GitHub Pages) โดยให้มันเรียก **ฐานข้อมูล/เซิร์ฟเวอร์ที่ยังรันอยู่บน Apps Script** ผ่าน API ที่มี Token ป้องกันไว้ วิธีนี้ทำให้หน้าตาไม่มีแบนเนอร์ของ Google อีกต่อไป แต่ **ต้องทำขั้นที่ 1-5 ด้านบนให้เสร็จก่อน** (Apps Script ต้อง Deploy แบบ Who has access = **Anyone** ด้วย)

1. เปิด repo GitHub ของคุณ (เช่น `Em-O-Cha/CRM-SpunkyFood`) ให้มีไฟล์ **`Index.html`** อยู่ที่ root ของ repo และเพิ่มไฟล์โลโก้ชื่อ **`Logo.png`** ไว้ข้าง ๆ (ไม่ต้องมีไฟล์ `.gs` ก็ได้ เพราะไฟล์เหล่านั้นอยู่ใน Apps Script อยู่แล้ว)
2. **(ไม่บังคับ แต่แนะนำ)** เปิดไฟล์ `Index.html` หาบรรทัด `var DEFAULT_API_URL = '';` (อยู่ต้น `<script>`) แล้วใส่ Web App URL ของคุณ (จากขั้นที่ 4 ด้านบน ลงท้ายด้วย `/exec`) ลงไปในเครื่องหมายคำพูด เช่น `var DEFAULT_API_URL = 'https://script.google.com/macros/s/xxxxx/exec';` — ใส่ตรงนี้ไว้ได้เลยเพราะ URL ไม่ใช่ความลับ (**ต่างจาก API Token ที่ห้ามใส่ในไฟล์นี้เด็ดขาด**) ทำแบบนี้แล้วตอนเปิดเว็บครั้งแรกจะไม่ต้องพิมพ์ URL เอง กรอกแค่ Token พอ — ถ้าข้ามขั้นนี้ก็กรอก URL เองตอนเชื่อมต่อได้เหมือนกัน ไม่บังคับ
3. ไปที่ **Settings → Pages** ของ repo → หัวข้อ **Build and deployment** → เลือก Source เป็น **Deploy from a branch** → เลือก branch `main` และโฟลเดอร์ `/ (root)` → กด **Save**
4. รอสักครู่ จะได้ลิงก์เว็บไซต์ เช่น `https://em-o-cha.github.io/CRM-SpunkyFood/`
5. เปิดลิงก์นั้น → จะเจอหน้าจอ **"🔌 เชื่อมต่อระบบ CRM"** เหมือนกับตอนเปิดตรงจาก Apps Script:
   - ช่อง **Web App URL**: ถ้าใส่ `DEFAULT_API_URL` ไว้แล้วในขั้นที่ 2 ช่องนี้จะกรอกให้อัตโนมัติ ถ้าไม่ได้ใส่ไว้ก็วาง URL เองตรงนี้ได้
   - ช่อง **API Token**: ถ้าเคยสร้างไว้แล้วตอนเปิดจาก Apps Script โดยตรง ให้ไปคัดลอกมาจากหน้า **"⚙️ ตั้งค่า" → การ์ด "การเชื่อมต่อ"** แล้ววางที่นี่ (ห้ามกดปุ่ม "สร้าง Token ใหม่" ซ้ำ เพราะจะทำให้ Token เดิมใช้ไม่ได้)
   - กด **เชื่อมต่อ**
6. เท่านี้ก็ใช้งานได้เหมือนเดิมทุกอย่าง ข้อมูลชุดเดียวกัน แค่หน้าตาไม่มีแบนเนอร์ของ Google Apps Script อีกต่อไป

**ข้อควรระวังเรื่องความปลอดภัย:** เมื่อตั้ง Who has access เป็น **Anyone** ใครก็ตามที่รู้ทั้ง Web App URL และ API Token จะเข้าถึงข้อมูลได้ ดังนั้น:
- **อย่า commit API Token ลงใน GitHub เด็ดขาด** — ระบบออกแบบมาให้ผู้ใช้กรอก Token เองตอนเชื่อมต่อครั้งแรก แล้วเก็บไว้ใน localStorage ของเบราว์เซอร์เครื่องนั้นเท่านั้น ไม่เคยถูกเขียนลงไฟล์หรือโค้ดที่ push ขึ้น GitHub
- ถ้าสงสัยว่า Token หลุด ให้ไปกด **"สร้าง Token ใหม่"** ที่หน้าตั้งค่าทันที (Token เก่าจะใช้ไม่ได้อีก ต้องอัปเดต Token ใหม่ในทุกเครื่อง/เบราว์เซอร์ที่เคยเชื่อมต่อไว้ด้วย)

## ⚠️ สิ่งสำคัญที่ต้องจำ: แก้โค้ดแล้วต้อง Deploy ใหม่ทุกครั้ง

ถ้าในอนาคตมีการแก้ไขโค้ด (เช่น ผมส่งไฟล์อัปเดตมาให้) หลัง copy โค้ดใหม่ไปวางแล้ว **ต้องกด Deploy ใหม่เสมอ**:
1. กด **Deploy** → **Manage deployments**
2. กดไอคอนดินสอ (แก้ไข) ที่ deployment เดิม
3. ที่ **Version** เลือก **New version**
4. กด **Deploy**

ลิงก์ Web app URL เดิมจะยังใช้ได้เหมือนเดิม ไม่ต้องส่งลิงก์ใหม่ให้ใคร

**Q: ข้อมูลเก็บอยู่ที่ไหน?**
A: อยู่ใน Google Sheet ชื่อ "CRM Spunky Food Database" ที่สร้างขึ้นในขั้นที่ 3 (อยู่ใน Google Drive ของคุณ) เปิดดู/แก้ไขตรง ๆ ในชีตได้เลยถ้าจำเป็น

**Q: ไฟล์เอกสารที่อัปโหลดเก็บที่ไหน?**
A: อยู่ในโฟลเดอร์ Google Drive ชื่อ "CRM Spunky Food Documents" (สร้างอัตโนมัติ)

**Q: ใช้ AI วิเคราะห์ลูกค้าแล้วเจอ error?**
A: ตรวจสอบว่าใส่ Anthropic API Key ถูกต้องในหน้า "ตั้งค่า" และบัญชียังมีเครดิตใช้งานอยู่

**Q: อยากให้เพื่อนร่วมทีมใช้ด้วย ทำยังไง?**
A: ตอน Deploy เลือก "Who has access" เป็น "Anyone with Google account" แล้วส่งลิงก์ Web app URL ให้ (ทุกคนจะเห็นข้อมูลชุดเดียวกัน เพราะเก็บในชีตเดียวกัน)

**Q: อัปเดตโค้ดแล้วขึ้นขอ Authorize ใหม่อีกรอบ ปกติไหม?**
A: ปกติครับ เกิดขึ้นเวลาโค้ดใหม่มีการขอสิทธิ์เพิ่ม (เช่น Drive/UrlFetch) กด Allow ได้ตามปกติ (เป็นสคริปต์ของคุณเอง ไม่ใช่ของคนอื่น)

**Q: หน้า "เลือกสินค้าที่สนใจ" ตอนสร้างดีลว่างเปล่า ไม่มีให้เลือก?**
A: ไปที่หน้า "⚙️ ตั้งค่า" กดปุ่ม **"ทดสอบการเชื่อมต่อ"** (การ์ด "ทดสอบเชื่อมต่อ Master Data Sales") จะบอกว่าเปิดไฟล์ได้ไหม มีแท็บอะไรบ้าง และอ่านสินค้าได้กี่รายการ ถ้าอ่านได้ 0 รายการ ให้ตรวจสอบชื่อแท็บ "SKU ส่งออก" ในช่อง "ชื่อแท็บสินค้า" ให้ตรงกับที่มีจริงในไฟล์ (ดูจากรายชื่อแท็บที่ปุ่มทดสอบแสดงให้) ระหว่างนี้พิมพ์ชื่อสินค้าเองในช่อง "หรือพิมพ์ชื่อสินค้าเอง" แทนได้เลย ไม่ต้องรอ

**Q: ปิดการขายสำเร็จแล้ว VAT/ค่าขนส่งคำนวณยังไง?**
A: ที่หน้าต่าง "ปิดการขายสำเร็จ" กรอก "ยอดขายสินค้า (ก่อน VAT)" ระบบจะคิด VAT 7% ให้อัตโนมัติ (ติ๊กออกได้ถ้าลูกค้ารายนี้ไม่มี VAT) แล้วกรอก "ค่าขนส่ง" เพิ่มได้ ระบบจะรวมเป็น "ยอดรวมทั้งหมด" ให้เอง และบันทึกแยกคอลัมน์ในชีต Revenue (Price = ก่อน VAT, Amount = หลังบวก VAT, Delivery = ค่าขนส่ง, Bill Total = ยอดรวมสุทธิ)

**Q: รายงานที่ส่งเข้ากลุ่ม LINE ตามตารางเวลา กับชีต Revenue คืออันเดียวกันไหม?**
A: คนละอันกันครับ รายงานที่ส่งเข้า LINE คือสรุปภาพรวมลูกค้า/ดีล/รายการที่ต้องติดตามในระบบ CRM (เหมือนหน้า Dashboard) ส่วนชีต Revenue คือบันทึกยอดขายที่ปิดสำเร็จแล้วแต่ละรายการแบบละเอียด (ราคา, VAT, ค่าขนส่ง, ลูกค้า ฯลฯ) ใช้คนละจุดประสงค์กัน ดูตัวอย่างข้อความรายงาน LINE ได้ที่หน้า "⚙️ ตั้งค่า" ปุ่ม "ดูตัวอย่างรายงาน"

**Q: รายการ Ad / Payment ตอนปิดการขายว่างเปล่า?**
A: เช็คชื่อแท็บที่ตั้งไว้ในหน้าตั้งค่า ("ชื่อแท็บช่องทางโฆษณา (Ad)" และ "ชื่อแท็บวิธีชำระเงิน (Payment)") ให้ตรงกับชื่อแท็บจริงในไฟล์ Master Data Sales แล้วกด "ทดสอบการเชื่อมต่อ" ดูผลอีกครั้ง ถ้ายังว่างสามารถปล่อยว่างตอนปิดการขายได้ (ไม่บังคับ)

**Q: กด "ปิดการขายสำเร็จ" แล้วยอดขายไม่เข้าไปในชีต Revenue?**
A: ต้องเป็นบัญชี Google เดียวกับที่รันสคริปต์นี้ที่มีสิทธิ์แก้ไขชีต "Revenue" (ค่าเริ่มต้นชี้ไปที่ชีตที่ให้ไว้แล้ว ถ้าจะเปลี่ยนไปชีตอื่นตั้งค่าได้ในหน้า "ตั้งค่า") ถ้ายังไม่เข้าให้เปิด **Execution log** (เมนู Executions ด้านซ้ายของ script.google.com) ดูว่ามี error อะไรขึ้นตอนอัปเดตดีล — ระบบออกแบบให้การบันทึกดีลสำเร็จอยู่แล้วแม้ส่งเข้า Revenue ไม่ได้ จะได้ไม่บล็อกการทำงานหลัก

**Q: อัปโหลดเอกสารแล้วไม่ขึ้นอะไรเลย/ค้าง?**
A: ไฟล์ใหญ่ (โดยเฉพาะ PDF สแกนความละเอียดสูง) อาจใช้เวลาสักครู่ในการแปลงและอัปโหลด ลองรอ 10-20 วินาที ถ้ายังไม่มีอะไรขึ้นและไม่มี toast แจ้ง error เลย ให้ลองไฟล์ที่มีขนาดเล็กลง (ไม่ควรเกิน ~15MB)
